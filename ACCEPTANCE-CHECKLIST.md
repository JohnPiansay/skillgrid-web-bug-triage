# Acceptance Checklist

Use this checklist for the workbench delivery. Keep an item unchecked unless the corresponding evidence exists.

- [ ] A separate report exists for each reported defect.
- [ ] Every report records the staging application/build and test environment.
- [ ] Each reproduced defect has minimal steps and expected versus actual behavior.
- [ ] Each defect is classified by affected area and user impact.
- [ ] Console, network, or screenshot evidence captured during reproduction is attached or linked for each applicable defect.
- [ ] Defects that could not be reproduced are explicitly marked and include the environment and attempts made.
- [ ] Evidence is readable, defect-specific, and sanitized of credentials, tokens, cookies, and unnecessary personal data.
- [ ] Delivery notes summarize verified outcomes and link to the reports.
- [ ] All statements are evidence-backed; no unverified defect or result is presented as confirmed.
